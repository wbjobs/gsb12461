# WebSocket 稳定性调试台

零框架、零运行时依赖的 WebSocket 调试工具。用于观察连接中断 / 重连 / 消息乱序 /
重复，并在重连后自动补偿丢失消息。全部使用原生 **WebSocket + Web Worker +
IndexedDB + DOM + Canvas** 实现。

## 快速开始

```bash
# 启动内置测试服务器（仅需 Node >= 18，零依赖）
node tools/server.js
```

浏览器打开 <http://localhost:8080/>，地址栏默认填 `ws://localhost:8080/ws`，
点击「连接」即可。服务器每 2 秒推送一条带递增序号的消息，并支持断线重连后的补偿。

> 也可连接任意自有 WebSocket 服务：直接在地址栏输入 `ws://` / `wss://` 地址。
> 非标准协议（无序号）的消息仍可收发，重复检测退化为内容哈希匹配。

运行自动化验收测试（内存中驱动真实 Worker 逻辑，无需端口/浏览器）：

```bash
node test/smoke.mjs            # 17 组，约 20s
node test/smoke.mjs --cap      # 额外验证重连上限，共 18 组，约 90s
```


## 功能

- 连接用户输入的 WebSocket 地址，发送 / 接收消息
- 每条消息展示 **序号、时间（毫秒）、方向（发送/接收/事件）**
- 断线后 **指数退避（1s→2s→4s…上限 30s，±20% 抖动）自动重连**
- 重连成功后自动发送 **sync 补偿请求**，拉取断线期间丢失的消息
- 实时检测并标记 **乱序（黄）、重复（紫，去重展示）、缺口（红）**
- 顶部展示 **连接状态、重连次数、补偿次数、补偿消息数、乱序/重复计数、退避倒计时**
- **IndexedDB 保存消息历史**，刷新页面后自动恢复最近 1000 条
- Canvas 消息时序图：发送/接收双泳道、缺口红色区间、补偿外圈、连接/断线事件竖线，
  支持滚轮缩放、拖拽平移、悬停查看详情、跟随最新
- 页面卸载（`pagehide` / `beforeunload`）时立即关闭 socket 并清空全部定时器

## 补偿协议（与调试服务器约定）

```jsonc
// 客户端 -> 服务端：重连成功后请求 lastSeq 之后的全部消息
{ "type": "sync", "lastSeq": 12, "ts": 1700000000000 }

// 服务端 -> 客户端：补回缺失消息（可为空数组）
{ "type": "sync", "from": 12,
  "items": [ { "seq": 13, "ts": 1700000001000, "text": "..." } ] }

// 正常数据帧
{ "type": "data", "seq": 13, "ts": 1700000001000, "text": "..." }
```

补偿对账：客户端维护「连续水位 + 缺口集合」。补偿数据按 seq 升序回填；
若补偿响应超时、发送失败或返回不完整（仍有缺口），按退避策略自动重试，
最多 **4 次**（初次 + 3 次重试），仍失败则在界面明确标记「补偿失败」。

## 异常链路处理对照

| 边界 / 异常 | 处理方式 |
| --- | --- |
| 地址非法 / 协议非 ws(s) | 立即 `connect_invalid`，输入框标红，**不触发重连** |
| 连接失败（拒绝/不可达） | `connect_failed` 后进入退避重连 |
| 连接超时（8s 未 open） | `connect_timeout`，关闭后进入退避重连 |
| 运行中断线 | `disconnect` 事件 + 指数退避重连，最多 **6 次** |
| 重连上限 | `reconnect_exhausted`，停止自动重连，等待手动连接 |
| 消息乱序 | seq 跳跃 / 小于水位时标记 `乱序` 并记录缺口 |
| 消息重复 | 相同 seq（或无序号时内容哈希命中）标记 `重复·去重` |
| 补偿失败（超时/发送失败/不完整） | 指数退避重试，最多 4 次，失败明确告警 |
| 页面卸载 | 发送 `dispose`：关闭底层连接、清空全部定时器、阻止重连 |

## 异常模拟面板（仅内置服务器）

连接内置服务器后，页面底部按钮可一键注入异常，便于验收：

- **服务器断链**：立即断开，触发退避重连 + 补偿
- **下一条重复**：同一序号发送两次，验证重复检测
- **下一条乱序**：相邻两条交换发送顺序
- **丢弃 3 条**：占用序号但不发送，重连后由 sync 补齐
- **丢弃且不响应补偿**：验证补偿超时 → 退避重试 → 最终成功

## 设计说明

- 连接状态机与协议逻辑全部运行在 **Web Worker** 中，避免补偿重试 / 退避定时器
  阻塞 UI；Worker 不直接写库，事件统一上抛主线程，保证「存储、列表、Canvas
  时序图」使用同一份数据源。
- 去重策略：有序号消息以 `seq` 为准；无序号消息使用 FNV-1a 内容哈希，去重窗口
  5 分钟（窗口内两条内容完全相同的无序号消息会被标记为重复）。
