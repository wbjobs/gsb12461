# WebSocket 稳定性调试器

零框架纯前端工具：连接用户指定的 WebSocket 地址，监控连接稳定性，
检测消息乱序/重复/丢失，断线自动退避重连并请求补偿，消息历史持久化，Canvas 时序可视化。

## 运行

静态文件直接用任意 HTTP 服务器托管即可（Web Worker 要求 http 协议，不能用 file://）：

```bash
npx serve .        # 或 python3 -m http.server
```

打开页面后输入 `ws://` / `wss://` 地址，点击「连接」。

## 功能对照

| 需求 | 实现 |
| --- | --- |
| 地址非法 / 连接失败 / 超时分别处理 | `js/connection.js` `validateUrl` + 分类错误（invalid / failed / timeout） |
| 断线退避重连 + 上限 | 指数退避（1s 起 ×2，上限 30s）+ 随机抖动，次数可配 |
| 乱序检测 | `js/sequencer-worker.js`：序号小于已见最大值即标记乱序 |
| 重复去重 | Worker 内 `seen` 集合判重，重复消息标记并默认在表格隐藏 |
| 补偿请求 + 重试 | 重连成功后发送模板 `{"type":"compensate","after":{{afterSeq}}}`，发送失败指数退避重试 3 次 |
| 状态 / 重连 / 补偿统计 | 顶栏实时统计（重连次数、补偿次数、补回数、乱序、重复、丢失） |
| 消息历史保存 | `js/store.js` IndexedDB，刷新后自动恢复并重建序号状态 |
| 时序可视化 | `js/timeline.js` Canvas，发送/接收双泳道，颜色区分乱序/重复/补偿 |
| 页面卸载清理 | `pagehide`/`beforeunload`：停止重连、关闭连接、终止 Worker、关闭数据库 |

## 消息协议约定

- 消息为 JSON 且含序号字段（默认字段名 `seq`，界面可改）才参与乱序/重复分析；纯文本消息只记录不分析。
- 发送时勾选「自动附加 seq」会为 JSON 对象消息自动填充自增序号。
- 补偿：重连后向服务器发送补偿模板，`{{afterSeq}}` 替换为已收到的最大序号；
  服务器应重发该序号之后的消息（参考 `test/ws-server.js`）。

## 测试

```bash
node test/run-tests.js
```

- 序号分析（乱序/重复/缺口/补回）与连接管理（地址校验、超时、退避、上限）为必跑项；
- 若本机允许监听端口，会自动启动 `test/ws-server.js`（模拟丢包 8%、重复 5%、乱序 7%、每 6s 断线）
  做端到端收发 + 断线重连 + 补偿验证。
